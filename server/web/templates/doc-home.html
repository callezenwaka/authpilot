How it fits your workflow

Development phase

Build your auth integration locally

  • Test OIDC, SAML, and WS-Fed flows without external accounts
  • Iterate on MFA — TOTP, push, SMS, magic links, passkeys
  • Debug tokens and assertions in real-time
  • Run integration tests in CI/CD with no external dependencies
Migration phase

Switch providers with zero code changes

  • Swap provider personalities — Okta → Azure AD → Google
  • Export user data and group mappings
  • Compare Furnace responses against real provider responses
  • Gradually shift production traffic while keeping Furnace for dev

What's included

Protocol support

Full OIDC, SAML 2.0, and WS-Federation implementations. Discovery, JWKS, token exchange, assertions — all included.

Provider personalities

Emulate Okta, Azure AD, Google Workspace, GitHub, and OneLogin — including their specific claim shapes and quirks.

MFA methods

TOTP, push notifications, SMS, magic links, and WebAuthn/passkeys — all simulatable without real authenticators.

SCIM provisioning

Full SCIM 2.0 for user and group management. Supports inbound provisioning and outbound push to an external SCIM target.

Real-time admin UI

SSE-powered dashboard showing live users, groups, flows, and sessions. Notifications update without a page refresh.

Multi-tenancy

Isolated tenant namespaces with per-tenant users, groups, and flows. Single binary, multiple virtual environments.

CI/CD ready

No external accounts or network calls. A single docker run starts a fully functional auth server for integration tests.

SQLite persistence

Data survives restarts when mounted as a Docker volume. In-memory mode available for stateless CI runs.

Quick start

Pull the published image and open http://localhost:8025 once the container starts.

docker run --rm \
  -p 8025:8025 \
  -p 8026:8026 \
  -v furnace_data:/data \
  callezenwaka/furnace:latest

The admin API key is auto-generated on first start. Find it at Admin UI → Config → Admin API Key.
